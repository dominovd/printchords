# PrintChords — сайт на Astro

Реализация `PROJECT.md` и `DESIGN.md`. Собраны два движка диаграмм — аккордовый
бокс и гриф — и шесть шаблонов: подборка, страница аккорда, хаб печати, пустые
листы, гаммы и пентатоника.

```bash
npm install
npm run dev        # http://localhost:4321
npm run build      # сборка в dist/
npm test           # 28 тестов: данные, рендереры, листы, гаммы, тексты
npm run check      # только валидация аккордовых данных
```

PNG и PDF не лежат в репозитории — они генерируются. Про это можно не помнить:
дев-сервер досоздаёт недостающие при старте, а сборка **падает**, если страница
ссылается на файл, которого нет. Если картинка не открылась, значит дев поднят
до появления новых данных: перезапустите `npm run dev` или выполните
`npm run assets`.

## Архитектура

```
src/
  data/chords.json      единственный источник аппликатур
  data/charts.mjs       описания страниц-подборок
  data/blanks.mjs       пустые листы и тексты /blank-chord-chart/
  data/scale-pages.mjs  тексты и FAQ страниц гамм
  lib/scales.mjs        интервалы, написание нот, боксы пентатоники
  lib/diagram.mjs       ЕДИНСТВЕННОЕ место, где рисуется гриф
  lib/chords.mjs        доступ к данным + всё производное (ноты, диапазон, сложность)
  lib/chord-page.mjs    тональности, советы по бою, FAQ из самих аппликатур
  lib/printables.mjs    реестр всех листов для хаба печати
  lib/scale-sheets.mjs  печатные листы гамм
  pages/index.astro     корень = Guitar Chord Chart
  pages/[chart].astro   остальные подборки
  pages/chords/[chord].astro  шаблон аккорда
  pages/printable-chord-chart.astro
  pages/blank-chord-chart.astro
  pages/guitar-scales/index.astro, pentatonic.astro
scripts/
  validate-chords.mjs   падает, если данные противоречат сами себе
  generate-images.mjs   PNG 1000×1500 на билде через resvg
```

**Одна функция `fretboardGroup()` рисует всё:** SVG на экране, печатную карточку
1000×1500, композит подборки и вектор для печати. Второго пути отрисовки не
существует, и тест `printable card and on-screen diagram draw the identical
fretboard` падает, если он появится.

**Ничего не написано дважды.** Ноты, диапазон ладов, сложность, «какие струны
глушить», тональности и половина FAQ вычисляются из `positions` / `fingers`.
Текст физически не может разойтись с картинкой.

## Что сделано по замечаниям к макету

| Замечание | Как решено |
|---|---|
| Карточка печати противоречит диаграмме (2 против 1) | Обе выходят из одного вызова `fretboardGroup()`; расхождение ловится тестом |
| «Pinky on 2nd string» с перекрещенными пальцами | Аппликатура исправлена на `[2,1,0,0,3,4]` — безымянный на 2-й струне, мизинец на 1-й; вариант переименован в «Four-finger G» |
| Точка у Bm без номера | Рендерер пропускает только те струны, которые реально закрыты барре; тест `no dot is drawn without a finger number` проверяет каждую |
| «Beginner three-finger» вводит в заблуждение | Переименовано в «1-2-3 fingering», подпись «Easier reach», в тексте прямо сказано: те же ноты, другая рука |
| Ссылки уходят на F, которого нет в плане | Блок «Learn these next» ведёт на D, A, B и Bm — на те, что могут ранжироваться. F остался диаграммой в подборках |
| Тексты описывают нашу архитектуру | Убрано; тест `copy talks about playing, not about the software` заваливает билд на словах вроде «rendered from the shared chord data» |
| «Strings: 6-string guitar» — строка без информации | Заменено на `Fret span` и `Difficulty`, обе считаются из аппликатуры |
| Панели и PNG должны быть в DOM при отдаче | Все четыре панели и все четыре `<img>` печатных карточек в HTML, переключается только видимость. Проверено с отключённым JS: 4 панели, 4 карточки, 12 диаграмм |
| Прозы на странице почти нет | Абзац ~150 слов на каждой странице аккорда (`intro` в `chords.json`) и три абзаца на подборке |

## Печать и артефакты

- **PNG 1000×1500** генерируются на билде в `public/img/` — реальные файлы,
  они же `og:image` и `media` для пина. 15 карточек аккордов + 2 листа подборок.
- **Каждый сгенерированный файл видим на странице. Осиротевших нулей.** Блок
  «Compare all N fingerings» показывает саму печатную PNG, а не SVG; на страницах
  гамм под каждой гаммой стоит галерея «в каждой тональности» с двенадцатью
  превью, ведущими в PDF. 93 PNG и 93 PDF, все со ссылкой из HTML и все в
  image sitemap. Проверяется скриптом при ревью, стоит держать это правило:
  файл, на который не ссылается ни одна страница, для поиска не существует.
- **Лист подборки — 3 колонки, не 4.** Холст 2:3: при четырёх колонках сетка
  занимала верхние четыре пятых, дальше шла пустая полоса, и в ленте Pinterest
  диаграммы читались мелко. Три колонки заполняют пропорцию и дают каждой
  диаграмме примерно на треть больше площади. Число колонок — поле `columns` в
  описании листа, по умолчанию 3; неполный последний ряд центрируется.
- **Листы подборок и пустые листы — одна раскладка.** `sheetSvg()` принимает
  массив ячеек; `chartSheetSvg()` подставляет аккорды с подписями,
  `blankSheetSvg()` — пустые сетки с линейкой для названия. Отступы правятся в
  одном месте.
- **`/printable-chord-chart/` — хаб, а не копия чарта.** Никакой сетки аккордов
  на нём нет: только превью всех пяти листов (реальные PNG), кнопки и текст про
  печать. Новый чарт или пустой лист попадает туда автоматически через
  `lib/printables.mjs`.
- **PDF — настоящие файлы, а не диалог печати.** `scripts/svg-to-pdf.mjs`
  проигрывает тот же SVG в pdfkit: 92 векторных PDF на A4 с встроенным Inter,
  текст выделяется. Транслятор понимает ровно те элементы, которые выдаёт
  рендерер, и падает на любом новом — фигура не может тихо пропасть из PDF.
  Путь выводится из пути картинки одним правилом в `lib/assets.mjs`.
- **Печать** осталась отдельной кнопкой: `window.print()` и печатный вектор в
  DOM. Без JS браузерная печать всё равно даёт корректные листы.
- Шрифт Inter лежит в `assets/fonts/` (для resvg) и `public/fonts/` (для сайта),
  чтобы PNG собирались одинаково на любой машине. У статических начертаний Inter
  нет знака `♭` (U+266D) — он рендерится квадратом, поэтому ступени пишутся как
  `b3`, `b7`. Это проверяется тестом.

## Гаммы

Второй рендерер — `neckGroup()` в том же `diagram.mjs`: гриф на 12–24 лада,
ступени в кружках, корень залит и подписан `R`. Цвета нет вообще, поэтому лист
переживает ксерокс.

**Написание нот по теории, а не по таблице.** `scaleNotes()` даёт до-минорную
пентатонику как `C Eb F G Bb`, а не `C D# F G A#`: каждая ступень получает свою
букву, а знак подбирается под высоту. Блюзовая `b5` — исключение: у неё нет
правильной буквы, и вместо `Fb` или `Bbb` пишется простое имя.

**Боксы пентатоники строятся из самой гаммы,** а не по фиксированным сдвигам. На
каждой струне бокс берёт две следующие ступени от корня на шестой струне — только
так получается настоящий третий бокс с растяжкой на струне G. Тест проверяет, что
в каждом боксе ровно по две ноты на струну и что боксы стыкуются без разрывов.

**Тональность — параметр `?key=`, а не отдельный URL.** В HTML отдаётся одна
тональность, остальные одиннадцать пересчитываются в браузере теми же модулями,
что использовал сервер. Это осознанное отличие от правила «все варианты в DOM»:
аппликатуры аккорда — содержимое страницы, а транспонирование — параметр, который
каноникал намеренно отбрасывает; рендерить все 60 сочетаний означало бы добавить
почти мегабайт разметки, которую нельзя индексировать. PNG при этом сгенерированы
на все 12 тональностей, чтобы ссылка на скачивание и пин всегда вели в файл.

## SEO-разметка и ассеты

- **Схема — `WebPage`, а не `WebApplication`.** Основной контент страниц это
  печатные листы, и разметка обязана описывать именно его. У каждой страницы
  `primaryImageOfPage` с `ImageObject` на лист 1000×1500, на корне дополнительно
  `WebSite` с названием PrintChords. Всё собирается в `lib/schema.mjs`.
- **`FAQPage` оставлен сознательно.** Rich results по FAQ Google убрал в мае
  2026, так что в выдаче разметка не даёт ничего. Она стоит несколько сотен байт,
  остаётся валидной и это тот формат, который разбирают ответные движки.
- **Image sitemap.** `scripts/image-sitemap.mjs` читает собранный HTML, забирает
  картинки, которые страница реально показывает, вместе с их alt и пишет
  `sitemap-images.xml`, добавляя его в индекс. Перечисляются только видимые
  ассеты: PNG остальных одиннадцати тональностей существуют ради ссылок на
  скачивание, их ни одна страница не показывает, и в карту они не идут.
- **Иконки** рендерятся из `public/favicon.svg` тем же resvg: 96×96 и
  apple-touch 180×180.
- **Никаких длинных тире в текстах.** Ни в копирайте, ни в alt, ни в title, ни в
  комментариях. Диапазоны ладов пишутся коротким тире (`Frets 3–5`) — это
  типографски верно и на AI-текст не похоже.
